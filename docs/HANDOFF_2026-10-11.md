## 5. How to work safely (rules learned the hard way)

- **One bounded change per commit.** Update `README.md` and `CHANGELOG.md` when behaviour changes.
  Append dated evidence to the blockers file and the registry; never overwrite old findings.
- **Deploy only as a stage package:**
  - build: `tools/deploy/make_package.py`, added to `build_2026_10_11.sh`;
  - rehearse: `tools/deploy/check_packages.py <pkgdir> <base> <head> <stage>`, plus the tamper
    tests with `ATLAS_TAMPER_STAGE`/`ATLAS_TAMPER_KIND`;
  - copy to the Jetson and check checksums;
  - rehearse on a scratch copy of the live tree;
  - install with the **rover parked and latched**;
  - restart only that stage's service;
  - run `tools/deploy/verify.sh <stage>`;
  - write a record in `docs/deploy/`.
- **Isolated end-to-end tests** (`tools/safety/e2e_estop_test.py`) must use a private DDS domain
  (`ROS_DOMAIN_ID=77`, `ROS_LOCALHOST_ONLY=1`), a private `ATLAS_ESTOP_PIN_FILE`,
  `ATLAS_ESTOP_EVENT_LOG` and `E2E_PIN`. The script now refuses otherwise. Last result: 48/48.
- **Never** ask the operator to press LB outside a planned release test. An LB hold released the
  latch once today and the rover moved about 5 cm.
- **Never** run `pkill -f` with a pattern that matches your own shell.
- **Never** reseed localization, drive, reboot, change network, motor calibration, EKF, AMCL or
  maps without Dhruv's explicit approval. Keep autonomy disabled.
- Before using a bag or log for timing, note that a boot can start with the wrong wall clock (today
  it was 6 h 20 min behind until NTP). Use monotonic time.
- Never commit credentials, `.env`, logs, bags or generated output. Never publish the SSID or
  `wifi.json`.
