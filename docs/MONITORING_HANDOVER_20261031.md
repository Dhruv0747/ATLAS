## Reading the data correctly

- **Missing is not healthy.** When a source is absent, its metric is simply not emitted. Grafana then shows **UNAVAILABLE**: that means *no information*, never "OK" or 0. Check `atlas_source_available` and `up` first.
- **Historical vs live.** A Grafana graph or `query_range` is history. Only a value whose scrape is recent counts as live:
  - `time() - timestamp(up{job="atlas-jetson"})` should be under 15 s;
  - `up == 1`.
  If the exporter is stopped, the last points stay in the graph with a visible gap after them; they are not current.
- **Stale.** `atlas_topic_stale == 1` means the topic's cached age is above its limit (`atlas_topic_freshness_limit_seconds`).
- **The exporter's own timestamp** (`atlas_exporter_observed_timestamp_seconds`) can lag the scrape by up to one 15 s cycle. That is a phase offset, not clock drift; the clocks agreed within 0.3 s on 2026-10-31.
- **Monitoring never commands the rover.** Use it as evidence, then confirm on the Jetson before acting.

## Useful PromQL

```promql
# Is data live right now?
up{job="atlas-jetson"}
time() - timestamp(up{job="atlas-jetson"})

# CPU spikes: max per minute, and the processes' view of load
max_over_time(atlas_cpu_utilization_percent[1m])
atlas_load1
atlas_cpu_utilization_percent > 75

# Temperature / memory headroom
atlas_thermal_max_celsius
100 * (1 - atlas_memory_available_bytes / atlas_memory_total_bytes)

# Stale or missing telemetry
atlas_topic_stale == 1
atlas_topic_available == 0
max_over_time(atlas_topic_age_seconds{topic="lidar"}[10m])
atlas_source_available == 0

# Camera (metadata only; Astra has no frame-health source)
atlas_topic_age_seconds{topic="camera_info"}
atlas_service_active{service=~"atlas-camera.*"}

# ROS / systemd service failures
increase(atlas_service_restarts_total[10m]) > 0
atlas_service_failed == 1
changes(atlas_service_active[30m])

# Did a CPU spike coincide with stale telemetry? (same timestamps)
max_over_time(atlas_cpu_utilization_percent[1m]) and on() (max(atlas_topic_stale) == 1)
```

## Correlating with journals and ROS logs

1. Note the time in Grafana. Its timezone is the browser's (IST); Prometheus stores UTC.
2. On the Jetson (clock in IST, NTP-synced), run read-only:
   ```sh
   journalctl --no-pager -o short-precise --since "2026-10-31 15:55" --until "2026-10-31 16:05" -u <unit>
   journalctl --no-pager -o short-precise --since "…" -u atlas-monitoring-watchdog -u atlas-monitoring-exporter
   ls -lt ~/.ros/log | head            # ROS 2 per-node logs (timestamps in file names and lines)
   ```
3. A one-scrape gap means ±15 s. Compare `atlas_service_restarts_total` steps against `Started`/`Stopped` lines in the journal.
4. Never paste raw journals, ROS logs or bags into the repository.
