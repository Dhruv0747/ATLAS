# On-demand local companion — 2026-09-18

## Purpose and boundaries

One small language model can provide text conversation without a cloud reasoning
request and explain the limited fresh telemetry snapshot supplied to it. It does
not make the Jetson faster, repair hardware, read arbitrary logs, learn driving
routes, replace Nav2, qualify encoders, or grant autonomous authority.

The existing deterministic voice status, weather and confirmed hardware-command
branches run first, unchanged. Only ordinary conversation tries the local model,
then falls back to the existing cloud conversation path if local admission or
inference fails. Model output goes only to the response/TTS path: it is never
passed back through the command parser. No model tools or actuator publishers.

**Speech recognition still uses the existing cloud transcription.** A local text
model plus existing local Piper speech is not an offline wake/ASR system. No new
ASR or wake engine was installed in this work. No new autonomous-driving test is
claimed. Offline microphone-to-speaker use is a separate feature.

## Resource policy

- A lightweight ROS subscriber/broker starts at login/boot; the large model does not.
- First deployment is **stopped-only**: fresh manual-only control policy with a
  latched remote stop, plus two seconds of fresh zero velocity commands. This is
  an admission check, not independent physical standstill confirmation.
- Loss of the gate cancels/unloads the model. The existing remote and watchdogs
  retain control; the broker cannot stop, move or reset the rover.
- One inference request; no inference queue. Owner-only Unix socket, localhost
  model API, bounded question/context/history/output, 25-second total deadline.
- Model unloads after 15 idle seconds; two CPU inference threads, low scheduling
  priority, 2,048-token context, 128 generated tokens, GPU offload.
- Require 1,900 MB available before load and retain a 700 MB reserve; deny on
  temperature >=78 C or unavailable measurements. These are conservative software
  thresholds, not hardware safety certification.
- systemd MemoryMax=2300M is an additional host-memory limit, **not a complete GPU
  unified-memory accounting guarantee**. CPU quotas are not relied on, because
  this user's CPU cgroup controller was unavailable in the preceding audit.
- English/Hindi/Hinglish prompts are supported by the policy, but model response
  quality must be measured. A small model can be wrong; it is not trusted to
  diagnose a physical fault or claim a completed action.

## Reproducible runtime

Existing JetPack R36.4.3 / CUDA 12.6, aarch64, Orin architecture 87. No JetPack,
driver, firmware, EKF, odometry, safety, navigation or sensor configuration change.

- llama.cpp v0.4.1 checkout `b29c606e28a01b1bc8c1351026a0fa6e616bf6c4`.
- Official Qwen `Qwen/Qwen3-1.7B-GGUF` revision
  `90862c4b9d2787eaed51d12237eafdfe7c5f6077`.
- Original Q8_0: 1,834,426,016 bytes; SHA-256
  `061b54daade076b5d3362dac252678d17da8c68f07560be70818cace6590cb1a`.
- Quantize Q8_0 to Q4_K_M locally with the pinned quantizer; this is requantization,
  not a claim of exact equivalence to quantizing original full-precision weights.
- Model/runtime live outside Git at `~/.local/share/atlas-llm/`.

`bash project_atlas/scripts/install_local_llm_runtime.sh` prepares only the runtime
and model, without enabling services. Source and model downloads are HTTPS and
the source revision/model checksum are checked. Do not run a compilation or a
model benchmark during a driving test.

## Deployment and use

After targeted tests and runtime validation, deploy `atlas_local_llm.py` and
`atlas_local_llm_client.py` alongside `atlas_voice_companion.py`; install
`config/local_llm.json` and the user service/drop-in from `project_atlas/systemd/user/`.
Enable `atlas-local-llm.service`; restart only the voice companion to load its
local-model opt-in. Do not restart the motor base, mux, EKF or Nav2 for this feature.

While stopped, say **“Hey ATLAS, explain what odometry means.”** Existing
**“Hey ATLAS, battery status”** still uses deterministic fresh telemetry, not a
model guessing a battery percentage. The existing Companion processing/status
line labels the last reply `LOCAL LLM`, `CLOUD LLM`, or `LOCAL RULES`.

Text-only checks, without speaking or commanding any physical action:

```bash
python3 ~/project_atlas/scripts/atlas_local_llm_client.py
python3 ~/project_atlas/scripts/atlas_local_llm_client.py --ask 'Hello ATLAS. What can you help me with?'
```

Live diagnostic topic: `/atlas/local_llm/state`. It includes loaded/busy state,
admission reason, model label, last generation latency and completion count.

Rollback: remove/disable only the `local-llm.conf` opt-in (or set
`ATLAS_LOCAL_LLM_ENABLED=0`), restart voice, then stop/disable
`atlas-local-llm.service`. Keep the model files if future evaluation is wanted.
